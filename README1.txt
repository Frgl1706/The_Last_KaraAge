文化祭 唐揚げ屋台 Webサイト
============================

■ 主なファイル
- 07_updated.html : 更新版Webサイト本体
- firestore.rules.example : Firestore Security Rulesの参考例（そのまま無検証で公開しないこと）
- images/01.png ～ images/08.png : 写真（PNG、1920×1080推奨）
- fonts/AprilGothicOne-R_v1.01.ttf : エイプリルゴシック（使用する場合）
HTMLと images / fonts フォルダーは同じ階層に配置してください。

今回のZIPには画像本体・フォント本体は含まれていません。各自の正規の画像・フォントファイルを所定の場所に配置してください。

■ 管理者モードの入り方
1. 画面下部の「その他」を開く。
2. 「管理者モード」のパスワード欄に次の文字を入力する。
   パスワード：karaage
3. 「ログイン」を押す。
4. 管理者パネルで「改善点をCSVに書き出す」などの操作を行う。

重要：このパスワードはHTMLのJavaScript内に書かれている簡易的な画面ロックです。
ソースを読める人には分かり、本当の認証・アクセス制御にはなりません。
公開用の管理者操作を守るにはFirebase Authentication等の認証とFirestore Security Rulesまたはサーバー側処理が必要です。
参考ルールでは安全のため、公開ユーザーによるコメント削除を拒否しています。そのまま使う場合、「全コメント削除」はFirestore側の権限で拒否されるため、Firebase Consoleから削除するか、管理者認証を別途実装してください。

■ 実際のアクセス数・売上／行列カウントを共有する設定
現在のHTMLには Firebase 設定の仮値「ここ」が入っています。
このままでは、サイト全体のアクセス数を取得できず、集計は複数端末で共有されません。

設定手順：
1. Firebase Consoleでプロジェクトを作成し、Webアプリを登録します。
2. Cloud Firestoreを有効にします。
3. Webアプリ設定から apiKey / authDomain / projectId を取得します。
4. 07_updated.html 内の firebaseConfig の「ここ」を実際の値に置き換えます。
5. firestore.rules.exampleを読み、用途に合うように確認してからFirestoreのRulesへ設定します。
6. HTTPSで公開し、違う端末・ブラウザーで投稿とカウントが共有されることを事前確認します。

Firestoreで使用するデータ：
- siteStats/main : pageViews（ページ読み込み回数）、sales（購入報告ボタンの押下累計）、queue（行列参加中の申告数）
- comments : レビュー
- feedback : ダメ出し・改善点
- deliciousVotes : 「おいしい！」投票

注意：ルールの参考例は公開読み取りや匿名投稿を前提とします。コメント・改善点はサイト訪問者が閲覧できるので、個人情報を書かないよう案内してください。カウンターもボット等による連続操作を完全には防げません。App Check、投稿レート制限、入力検証を検討してください。
「allow read, write: if true」のような全面公開ルールは設定しないでください。

■ カウントの意味（誤認防止）
- 「アクセス」：Firebase設定後、ページが読み込まれた回数です。再読み込みもカウントされ、ユニーク人数ではありません。ボットや連続アクセスを完全には除外しません。
- 「買ったよ！」：ボタンが押された回数の累計です。POSレジと連動していないため、会計上の売上額や販売実績を保証するものではありません。公開ボタンは来場者が何度でも押せます。
- 「並んでる！」：そのブラウザーで行列参加を申告すると+1されます。同じブラウザーでは重複参加を抑止し、「列から抜けた」で-1します。端末変更・ブラウザーデータ消去・押し忘れで実際の人数と差が出ます。
- Firebase未設定／接続できない場合：購入・行列・改善点・レビューの一部は端末内に保存されます。端末内の保存内容は別の来場者と共有されず、実アクセス数としては表示されません。

模擬店の混雑時に正確な会計・行列管理が必要なら、「買ったよ！」を来場者任せにせず、スタッフだけが押せる管理画面やPOS集計を使ってください。このページの購入・待機カウントは申告を集める補助機能です。

■ ダメ出し・改善点とCSV
改善点は、Firebase設定済みで共有先へ接続できる場合、Firestoreの feedback コレクションに保存され、コメントタブの「ダメ出しを見てみる」スライドインに表示されます。
「その他」→「管理者モード」→「karaage」→「ログイン」→「改善点をCSVに書き出す」で、現在取得できている改善点をCSVとしてダウンロードできます。UTF-8 BOM付きなので、Excelで日本語を開きやすい形式です。

ブラウザーの安全仕様上、公開サイトのJavaScriptがサーバー上のCSVファイルへ勝手に追記・上書きすることはできません。そのため、このサイトではFirestoreを共有元データとして使い、CSVを必要時に書き出す方式にしています。Firebase未設定時は、その端末のlocalStorageにある改善点だけをCSVに出力します。

■ 本番前の最低確認
- 実際に使用するスマートフォン2台以上で、投稿・表示・カウント共有を確認する。
- ネットワークが切れた場合の表示と、復帰後の動作を確認する。
- 管理者パスワードだけでは管理機能を守れない点を理解し、公開前に管理者権限を設定する。
- 個人情報、電話番号、住所などを書かないよう、投稿欄の利用方針を案内する。
- 行列カウントは実人数の代わりにせず、必要ならスタッフが目視確認する。
